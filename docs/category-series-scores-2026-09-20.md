# 分类光泽、系列目录与观察日志歌谱

日期：2026-09-20，验收更新于 2026-09-21。以下保留本阶段的实现与验收数据；Series 简化题签、虹彩强度和最终部署状态以 [后续发布记录](category-resource-release-2026-09-21.md) 为准。

## 核查与依据

- 原有方案记录于 [本地后台体验记录](admin-ux-plan-2026-09-15.md)。共享 CSS 中的部分预设以单个渐变替换整个纹理，`ripple` 使用重复径向渐变，形成明显同心圆；另外组件 SCSS 还保留另一组光泽定义，职责重复。
- 学习 [原案例](https://poke-holo.simey.me/)、[基础光泽分层](https://github.com/simeydotme/pokemon-cards-css/blob/main/public/css/cards/base.css) 与 [普通镭射卡](https://github.com/simeydotme/pokemon-cards-css/blob/main/public/css/cards/regular-holo.css)：纹理、色彩反射与表面高光分别混合、使用不同背景尺寸和位移。采用本站原创 CSS，不下载卡牌素材或照搬高强度效果。作者也说明这是 [演示项目而非可直接安装的模块](https://github.com/simeydotme/pokemon-cards-css/issues/19)，因此限制层数并保留减少动态模式。
- 分类图片来自 `src/assets/images/accordion/*.webp`，由 Astro 导入后随 Pages 发布；不能因站点使用 Cloudflare 就把它们称为 R2 图片或实时图片变换。需分别核对本地格式／体积与线上缓存响应。
- Series 索引当前使用 `category.title`、`subtitle` 和 `series.title`，尚未统一英文；条目用上下横线分隔，分类题签较小。
- 用户已有未提交的文章修改及 02 文件名更改：保留这些改动，仅在两篇观察日志的歌谱位置整合内容。02 正文明确记录《慈光歌》（380），03 标记《耶稣基督是生命源》（323），按正文对应而非附件先后顺序。

## 实施计划

1. 核对角色图片的完整显示、裁切和传输链路，修复图片布局问题；记录 WebP 与 Cloudflare 缓存的区别。
2. 合并光泽来源，八种预设共用多层反射结构，以配色、纹理和方向形成差异；去掉同心圆和锥形渐变尖点。保留花体角色名、比例和选择行为；键盘／触摸有静态反馈，减少动态时不跟随指针。
3. Series 总索引统一英文，分类作为左侧分组标题，右侧以标题、介绍、数量组成无边框目录；手机单列。系列详情使用英文系列元数据，目录优先使用文章已有英文标题／说明，缺省时沿用内容系统原文回退；不改作者正文。
4. 根据用户照片转录两份简谱到 `.jly`，生成 SVG／校验元数据，嵌入各自文章。保留歌词、拍号与升降记号；不凭空补写看不清的作者信息。
5. 运行类型、内容、简谱与生产构建检查；浏览器核对桌面／手机、键盘、减少动态、卡片图片和两个谱面。补充必要回归测试及日志。

## 验收记录

### 光泽与图片

- `src/styles/category-foil.css` 是前台／后台共同的光泽来源。细纹、彩色干涉带、宽幅反射与独立表面高光组合，分别使用不同尺寸／位移；八个稳定预设 ID 保留。`ripple` 改为交错宽光带，不再使用重复径向圆环；移除 SCSS 中重复光泽和失效色变量。
- 光泽位于图像／遮罩之上、题签之下；面部和文字区域降低反射。只在指针输入时更新，不增加动画循环；减少动态时固定反射位置并关闭过渡。
- 分类图片原本已经是 WebP。线上样本 `/_astro/accordion_weiser.3MJIlfyS.webp` 返回 `server: cloudflare`、`cf-cache-status: MISS`、`cache-control: max-age=14400`，212704 字节与本地原图一致。这证明请求经过 Cloudflare，但不能证明启用了 Cloudflare 图片变换、Polish 或 R2；本轮没有改 Cloudflare 控制台设置。
- 依据 [Astro 图片指南](https://docs.astro.build/en/guides/images/)，在构建端用 `getImage` 生成 480／800 宽、quality 85 的 WebP，通过 `srcset`／匹配实际断点的 `sizes` 选择。七张图的 480 档约 57–129 KiB，800 档约 109–304 KiB；最大源图约 1278 KiB。保留源图，使用带哈希地址和懒加载。后台上传到 `/media/` 的图已有单独处理，本次不重复转换。
- 桌面完整加载后七张图片的布局规则一致；已检查的可见角色为全身显示，未复现反馈截图中的半截加载。显式设置卡片内部 span 为块盒；不能把未复现的问题归因于 Cloudflare。

- 修复元数据解析遗漏数字键 `1=` 的问题，支持附点弱起和中文歌词分组的文字回退；补充对应回归测试。

### 检查结果

- `npm run check`：类型检查零错误／警告，102 项单元测试、85 个内容文档、30 个静态页面；三份简谱缓存校验通过。
- 当前机器原生 Satteri 仍受 Windows Application Control 限制，沿用此前验证的 `.tmp/admin-wasi` 官方 WASI 后端运行检查；没有修改系统安全策略或项目依赖。
- 首轮 22 项页面回归中 20 项通过，两项旧章节测试在 `page.goto` 等待外部资源 `load` 时超时；改为 `domcontentloaded` 后仍用页面元素断言就绪。最终 **22 项公开页面回归全部通过**，另 **2 项后台分类／新增流程回归通过**。覆盖 320／390／768／1440 宽度、章节边界、无 JavaScript、键盘、减少动态、两份谱面和后台光泽选择。
- 人工查看了桌面／手机截图，以及两份完整 SVG：Series 无横线分组，卡片没有圆环，歌词对齐到曲末；手机谱面在自己的区域内横向滚动，正文不横向溢出。截图与运行日志保存在被忽略的 `.tmp`；`git diff --check` 无空白错误。
