# Telysta 视觉优化计划

2026-11-22 · 依据现有源码、设计规范与本轮截图。以下色值和尺寸用于出样。

## 现行规范与问题

Telysta 的特点来自暗色底、较松的长文节奏、现有字体、首页角色插画与偶尔出现的星空互动。保留系统无衬线正文、Cinzel 品牌字和首页既有的 LXGW WenKai。公开页延续阅读感，后台采用同一配色的紧凑工作区。

| 在哪里看见 | 代码里的原因 | 改动方向 |
| --- | --- | --- |
| 书籍详情「在线阅读」和下载链接同样亮 | `tokens.css` 的 `#9cc7e8` 同时承担链接、焦点、边框和状态。书籍详情把在线读与下载拆成两组，标题又写成「选择格式」 | 同一个文件的格式、大小、阅读、下载放在一行，让阅读按钮先被看见 |
| 站点设置需要一路向下找 | 每组配置连续堆叠，条目介绍与编辑按钮各占一行。`.records > li` 有间距属性，但没有定义行内布局 | 按用途跳到配置组，组内以同一列线对齐描述和操作 |
| 备份名称和链接黏连，登录设备输出长串 UA | 备份视图直接追加两个行内元素。登录设备直接拼接设备标签、浏览器原始标识和日期 | 主体、说明、操作用明确的列。设备显示人能识别的名称 |
| 文章列表横向跨度过大，同时上下滚动多 | 表格占满工作区，标题、状态、日期和操作使用固定百分比。分开的标题、操作与搜索行占用首屏 | 限制任务区内容宽度，标题和工具栏合并，固定元数据及操作列宽，让标题占剩余宽度 |

`DESIGN.md` 与设计 Skill 目前都把月光蓝指定给多种交互。第一阶段出样后，把两处改写成按角色用色的规则，另将分形写成可降级的背景场景。这样后续组件不会自动继承同一种亮蓝链接，也能区分长文需要的留白与后台需要的信息密度。

## 第一阶段 · 配色与书籍操作

- 以夜蓝黑为共同背景，比较两种低饱和配色。方案 A 用偏暖的灰白 `#e6e0e6`、次级灰 `#a19ba9`、灰紫交互色 `#b8b2ca`。方案 B 让交互改用偏暖灰粉 `#c7aabc`。用同一书籍和配置内容比较。键盘焦点单独使用更清晰的 `#c8c3de`，输入边线、选中面和错误分别定义，正文链接用下划线保留辨识度。
- 书页保留左封面、右书名与书目。文件区每一格式一行，依次显示格式、大小、在线阅读和下载。只有一种格式时移除「选择格式」。多格式保持相同列线，手机将操作放在同条文件信息下一行。PDF 阅读继续在新标签页打开。公开书与已授权书调用同一套布局规则，现有访问检查与下载参数沿用。
- 评论区优先确认访客的「登录后参与讨论」和登录后的编辑框都清晰。原有灰粉樱花放在末端留白，延续二次元的细节感。读者进入正文时，封面、作者和标题先于装饰被看到。

## 第二阶段 · 后台减少滚动与视线跨度

左侧分组导航保留。右侧只显示一个当前任务标题，语言切换留在顶部。列表任务宽度先试 1120 CSS px，设置与设备先试 960 CSS px，长文编辑器由实际内容决定。行内以 8、12、16、24px 建立间距节奏。移动端让说明自然换行，触控操作保留足够的点击区域。

| 页面 | 排版与操作 | 验收 |
| --- | --- | --- |
| 站点设置 | 顶部按用途定位分组，默认展示常用组，其余一键切换。桌面每行左边名称和一句用途，右边编辑。当前分组、搜索结果和返回位置可恢复 | 进入高级设置无需翻过其它分组。搜索支持跨组，搜索结果说明归属。单页消除 `1 / 1` 分页 |
| 数据备份 | 一个对齐的清单。左边数据范围，右边带文字的下载动作，单独突出整站管理数据。保留一段说明交代对象存储原文件的备份方式 | 1440×900 下主要备份项首屏可见。键盘和读屏能分辨每个导出范围 |
| 登录设备 | 第一行显示如「Chrome · Windows」和「当前设备」，次行显示已有的登录时间，末尾对齐退出操作。识别不到时显示通用设备名称 | 长 UA 不撑开页面。设备退出和确认流程仍可键盘完成 |
| 文章列表 | 搜索与新建放进同一工具栏，标题列弹性伸缩，日期、状态与行操作宽度一致。行高先试 44–48px，超长书名或文章名可换行 | 1440×900 首屏目标至少显示 10 条普通长度标题。移动端显示使用真实长中文、日文和英文标题核验 |

参考 Carbon 的表格工具栏、行高与分页安排，GOV.UK 的条目描述和行末操作。借用信息组织方式，表面、字色和边界沿用 Telysta 自身的风格。[Carbon Data Table](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines) · [GOV.UK Summary List](https://design-system.service.gov.uk/components/summary-list/)

## 第三阶段 · 星空与分形背景彩蛋

Shadertoy 是主要视觉参考。关注反复折叠产生的尺度、稀疏区域通向密集区域的过渡，以及相机几乎静止时仍能看见的细节。截图所示的 4D Apollonian 可作尺度和构图参考，《天体仪的呼吸》可作运动速度与留黑参考。浏览工具未能打开对应原站页面，这两例的视觉描述来自用户截图。逐作品核对源码和纹理许可，需要引用时记录作者、链接和授权。[Shadertoy · mrange 作品](https://www.shadertoy.com/view/N3VXz1) · [用户提供的 Bilibili 参考](https://www.bilibili.com/video/BV1doH36JEy8/) · [GLSL 分形技法与源码](https://darkeclipz.github.io/fractals/)

| 候选 | 视觉方向 | 试作路径 |
| --- | --- | --- |
| 阿波罗尼奥斯分形 | 大圆套着精细轮廓，形态像残缺的天球仪。少量局部着色 | 先用 2D 递归构图，再试球反演与轻量 3D ray marching。[The Coding Train](https://thecodingtrain.com/challenges/182-apollonian-gasket) |
| Julia 集 | 暗底上展开丝状边界，在边缘留下微弱青灰或紫灰色层次 | 自写 GLSL 逃逸时间与轨道着色，另比较 2D 静帧。[fractals-js（MIT）](https://github.com/delimitry/fractals-js) |
| 分形火焰 | 局部出现像雾或光尘的密度纹理。让亮部从画面外围缓慢显现 | 用迭代函数系统先试密度、色调和静帧。参考原作者的公式和 GPL-3.0 渲染器，站内试作独立撰写。[Scott Draves · flam3](https://github.com/scottdraves/flam3) |
| 递归枝纹 | 像海藻、霜纹或樱枝的结构从边角铺开，适合较轻的场景 | 以 L-system 或分叉树生成，先做静帧和轻微整体运动。[The Nature of Code · Fractals](https://natureofcode.com/fractals/) · [p5.js 示例源码（MIT）](https://github.com/nature-of-code/noc-examples-p5.js-archived) |

接入方案先在首页试行。首次进入公开站点时，以星空为常态，小概率随机抽到一个分形，当前标签页会话保持同款。跨页返回和调整窗口宽度沿用同一随机种子。选择范围在数据中维护。分形主体偏向画面外围，沿用深背景，并让中央文字区的对比度独立于场景。宽屏允许看见较完整的结构，手机单独裁构图。

沿用现有背景的挂载与卸载时机，Canvas 2D 和 WebGL 各用合适的画布，场景之间只保留一个活动渲染器。增强场景首屏之后才加载。滚离首页主视觉、标签页隐藏或界面被模态层遮住时暂停。开启减少动态时显示静帧，WebGL 不可用或上下文丢失时降级到静态背景或现有星空。后台和书籍阅读器用稳定的深色工作面。

## 验收与交付顺序

本地样张已用自写的 GLSL 与 Canvas 试出四种分形，并提供星空、旧亮蓝和两套新配色的对照。设置样张可以切换分组。书籍按钮和设置编辑用样例数据验证布局，不连接生产数据。

1. 固定同一批样本做对照，使用书籍详情、文章列表、设置、备份、登录设备和首页。先确认颜色和组件网格，再改共享规则和实现。书室分页、画廊首屏、博客正文、评论和登录页同步做视觉回归。
2. 检查 1440、768、390、320 CSS px、200% 缩放，覆盖中英界面、长标题、键盘焦点和减少动态。文字和链接在实际复合背景上测对比度，普通文字以 4.5:1 为最低目标，必要边界和焦点以 3:1 为最低目标。
3. 分形先给可切换的样张，确认其在文字下的实际亮度，再测生产预览。高像素密度与移动端比较星空基线，记录首屏、滚动和长任务差异。验证同一会话的随机场景稳定、关闭或返回能清理画布、减少动态有效。先以稳定的二维场景接入，三维的成本单独验证。
4. 视觉验收后更新 `DESIGN.md` 与 `telysta-design-guardian` 的配色、后台布局和背景条款。发布时分别验证主站和账户 Worker，保留退出分形试验的配置。功能与部署依赖见 [平台路线图](platform-roadmap-2026-11-16.md) 和 [后台产品化文档](console-product-redesign.md)。
