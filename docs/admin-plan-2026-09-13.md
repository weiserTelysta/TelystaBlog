# 后台实施计划：先本地可用，再评估云端

状态：**第一版方案与阶段验收记录**。2026-09-15 的最新优先级、实现范围与未完成项已移至 [UI 与功能补全计划](admin-ux-plan-2026-09-15.md)。本文保留第一版的决策依据，以下“第一版限制”不代表当前能力；尤其头像／分类／系列新增、图标预览和二维码地址已经补齐。日常操作以 [使用说明](local-admin.md) 为准，云端认证与 CMS 比较参考 [技术研判](local-admin-assessment-2026-09-13.md)。整个云端后台愿景尚未完成。

## 目标与推荐

作者通过本地浏览器，按功能维护站点内容、Hero、头像、标签页祝福、导航、联系方式、分类和文章；保存后能预览差异、检查构建，再手动提交和推送。保留现有静态网站、Git 版本与 R2 文件分发。

建议第一版采用本地模式：不需要先完成云端 GitHub 登录、DNS 分流和上传服务，就能解决日常修改配置的问题。云端可以继续做，但应在内容模型和安全保存已稳定后复用同一数据结构扩展，不维护第二份“云端配置”。

## 入口与日常流程

**已实现入口**：独立 `npm run admin`，仅绑定 `127.0.0.1`，默认地址 `http://127.0.0.1:4323/`。可用 `TELYSTA_ADMIN_PORT` 更换端口；占用时明确失败。网站仍另运行 `npm run dev` 预览，后台不依赖 Astro 预检成功，也不会出现在生产 `dist/` 中。

可以先启动网站，再启动后台；后台也必须能单独启动。原因是现有 `dev` 会先执行内容和简谱检查，坏文件可能让网站预览起不来，但编辑器必须还能打开来修复它。之后可增加一个开发启动器并行启动两者，但不能让预览检查失败同时杀掉编辑器。

进入方式采用终端 URL／浏览器书签；不放入公开站点导航。第一版本地模式不需要 GitHub 登录，服务端检查 Host、Origin、Fetch Metadata、随机会话令牌与固定可写路径。不为 `/telysta-admin` 名字额外维护代理。

未来启用云端时，可以在 `admin.telysta.com` 部署独立后台并使用 GitHub 授权；`telysta.com/telysta-admin/` 可作为便于记忆的跳转入口。作者已表示路径不重要，因此优先选择易部署、与公开页面隔离的入口。云端版本需要明确的认证／写入服务，不能仅把本地模式静态上传到 Pages。

日常流程：工作区干净时同步 Git → 启动编辑器与预览 → 修改／保存 → 查看差异 → 运行检查 → 作者 commit／push → 查看 Actions 结果。保存不自动提交，不自动上传 R2，也不自动上线。

## 功能分组与第一版边界

| --- | --- | --- |
| 站点身份 | 名称、默认与首页 SEO 描述、固定分享图；当前已有的可选备案文字 | 区分普通标题、分享卡片与标签页隐藏标题；通用版权／多链接页脚属于新增功能，另行设计 |
| 首页内容 | 介绍、区块、排序、启用；Hero 欢迎语在此提供直达入口 | 只支持现有区块类型，不让表单编写组件代码 |
| Hero 欢迎语 | 句子、稳定 ID、昼夜偏好、权重、mood；支持换行文本 | 已复用网站算法按指定小时试抽样；逐字／淡入效果通过网站预览核对，后台不复制第二套动画 |
| 头像与访问身份 | 已有方案的名称、alt、tone、启用、权重 | 头像与 favicon 预览；禁止全关，保护现有 ID 与头像表达式；新增／替换配套图片仍走维护脚本 |
| 标签页祝福 | 单独编辑多语言字符串列表，新增／删除／搜索 | 模拟离开与返回标题；至少一句非空；不伪造当前没有的语言、时段、权重字段 |
| 导航与联系 | 顶部菜单、首页社交、标签、链接、排序、QQ／微信二维码 | 图标只能从已有类型选择；二维码支持本地替换和扫码验证，缺图不能悄悄保存成功 |
| 分类与角色展示 | 英文角色题签、完整所属名称预览、中文展开文案、裁切位置 | 当前框宽:高 2:5，提供裁切预览；图片导入与分类 ID 受保护。图片替换选择器属于后续增强 |
| 系列与文章 | 编辑已有系列资料；按分类目录创建草稿，编辑完整 Markdown；9 月 15 日增加元数据表单与正文预览 | 表单只改动指定 YAML 值，正文与未知字段保留；分类／系列一致性、日期、序号及版本在保存前校验。文件导入／删除留到后续 |
| 素材选择 | 从已有 CDN 清单和本地登记图片搜索、预览、选择、复制引用 | R2 继续存文件；首期不做全 bucket 浏览、批量上传和远端删除 |
| 检查与历史 | 修改文件列表、保存前后源码、检查日志、本地 Git 历史 | 第一版只读历史，不提供恢复、reset、rebase、强推按钮；目前为完整源码对照，行级高亮差异后续增强 |

类型、字段和值以现有代码为准。本版直接编辑固定 TS 声明中的字面量，不迁移成第二套 JSON：TypeScript AST 提供表单结构，服务器补充枚举、范围、ID、占位符、链接、头像与二维码约束。导入、派生表达式、交互参数只读；源文件含不支持结构或语法错误时拒绝写入。这个适配器只支持登记过的声明，不是通用 TypeScript 编辑器。

配置抽离仍有价值，但当前配置已集中，先迁格式会同时引入数据迁移和 CMS 集成风险。待日常编辑模型稳定，再评估将纯数据迁入独立文件；一次迁移必须同步网站读取端，不保留两份来源。

## 头像、素材与 R2

不需要先建设完整“媒体库”。建议界面叫**素材选择**：帮助作者知道某张图是什么、用于哪里、如何引用；它是 R2 文件的索引入口，不是另一套存储。

头像维护分成两类：第一版可调整已有 7 套方案的启用、权重、名字和样式；新增方案作为后续受控流程，先准备 384×384 头像并上传 R2，再生成本地 32／48px favicon，最后登记配置。普通保存不能只改头像 URL 却遗漏 favicon。为了核对指定方案，后台提供独立预览；不把调试重抽按钮加进公开首页。

普通文章图片和二维码可受限上传至已有本地目录，只创建新 PNG／JPEG，不覆盖旧图。本版采用两步操作：先上传成功，再填写并保存引用；不是多文件事务。中途放弃会留下未引用的新图，但不会破坏旧引用，提交前用 Git 差异确认图片与配置一同提交。R2 新原图、大插画、封面压缩和资源清单生成继续沿用维护命令，不自动触发同步。

素材选择已提供清单键、公共显示图 URL、已登记尺寸，另外索引 7 套头像、本地 favicon、二维码和角色图。缩略图可用 cover，复制地址使用 display。本地图片缺少尺寸时标为未登记；不声称已完成全站引用扫描或覆盖清单外的文章配图。原图／资源发布编辑器和引用位置反查留到后续。

Git 的 `pull` 不同步外部原图；未来云端上传前，必须设计 R2 原图与本地素材目录的同步方式，否则本地重新生成清单可能丢掉云端新条目。当前第一版不引入这条新写入路径。

## 历史与恢复的慎重处理

第一版只展示差异和历史。恢复继续交给作者使用 Git 工具检查后处理，后台不替作者执行破坏性操作。

如果以后确需恢复功能，应先选择版本和文件、展示完整差异、检查未保存改动及资源引用，再生成“恢复提案”；作者确认后形成一个新提交，并重新校验与发布。不做整仓强制回退，不覆盖本地未提交修改，不删除 R2 对象。Git 版本只能恢复文件引用；若旧图片已删除，不能声称恢复完整网站。

## 实施阶段与验收

1. **文档核对与收敛（完成）。** 建立功能地图、修正操作指南、归档七份旧阶段文档；当前事实、历史记录、未来计划分别维护。
2. **技术选型验证（完成代码级评估）。** 检查 `@keystatic/astro@6.0.0`、`@keystatic/core@0.6.9`：版本声明支持 Astro 7，但本地更新处理直接写入 additions/deletions，未携带预期文件版本。该判断来自所检查版本的 `dist/keystatic-core-api-generic.node.js`，不是所有 CMS 的普遍结论，也不是已完成 CMS 浏览器集成。Decap 代理仍需配置存储映射，官方说明本地不支持 editorial workflow。两者都不能直接解决本项目的 TS 保真与冲突要求，因此改为受限本地适配器；试装依赖已移除。[Keystatic 本地模式](https://keystatic.com/docs/local-mode)、[Decap 本地代理](https://decapcms.org/docs/decap-proxy/)
3. **配置管理核心（已实现）。** 14 个功能入口，固定声明白名单、字面量编辑、源码对照、版本冲突拒绝、业务约束与部分即时预览；不迁移数据格式。含作者注释的列表允许改已有值，结构增删若无法保留注释则拒绝。
4. **文章与素材核心（已实现）。** 原始 Markdown 编辑、新建草稿、已有 R2／本地素材索引、受限新图片上传、只读 Git 历史及 `npm run check` 日志。现有路径受保护，删除和重命名不在本版开放。
5. **云端扩展评估（可选）。** 日常使用稳定后，再决定 GitHub 登录、私密草稿、独立托管、发布状态与 R2 上传。不是本地第一版的前置条件，也不承诺无需适配即可切换。

9 月 15 日先实现文章元数据表单与隔离正文预览，见 [写作阶段记录](admin-writing-2026-09-15.md)。随后按使用反馈优先补齐列表编辑、头像配套登记、分类角色联动、系列新增和图片处理，见 [最新计划](admin-ux-plan-2026-09-15.md)。下一步是图片替换、反向引用与 R2 单对象上传；在线身份认证仍单独规划。

验收使用临时目录样本，不改作者真实内容。检查非法值、来源校验、目录越界／联接、同名上传、文件版本冲突、TS 无修改往返、Markdown 原文保存、桌面／手机操作、键盘与减少动态；再运行全项目检查和公开页面回归。版本校验可防止读后发生的常见外部修改，但没有与 VS Code／OneDrive 共用操作系统事务锁，最后一次核验与替换之间仍有极小竞争窗口；不能宣传绝对不会丢失任何并发修改。保存旧字节副本供人工核对，仍需避免同时编辑同一文件。

第一版不包含在线 GitHub 登录、远程发布按钮、恢复按钮、R2 全库管理、自由 CSS／动效编辑或任意代码执行。成本集中在配置 schema、无损保存和预览，而不在搭建服务器。
