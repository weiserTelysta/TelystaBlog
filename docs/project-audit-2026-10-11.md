# 项目排查与修复记录：2026-10-11

当前的 Astro 静态站点、本地后台和离线素材工具分工适合个人博客维护，本轮未发现需要更换框架或重建内容系统的问题。确认的问题集中在输入校验、日期一致性、弹窗生命周期、并发写入和依赖版本，已逐项修复并加入回归验证。现有深色阅读风格、文章路径与评论映射继续保留。

- 检查本地后台请求边界、路径处理、版本冲突、保存、新建文章、素材响应和隔离预览。

## 架构评估

| 边界 | 现状与判断 |
| --- | --- |
| 页面与内容 | Astro 路由读取 Markdown 和共享元数据，公开文章、搜索、系列、sitemap 使用同一内容来源；继续保持 URL 与 pathname 评论映射稳定 |
| 配置与组件 | 文案和作者选项位于 `src/config`，组件负责渲染与交互；本地后台直接编辑现有源码，没有另一份配置数据库，适合当前维护规模 |
| 后台与公开站点 | 管理服务仅绑定回环地址，并检查 Host、Origin、会话令牌及登记路径；隔离预览和版本冲突有测试。服务不进入静态部署产物 |
| 资源与发布 | 作品条目决定收录，CDN 清单负责文件地址和尺寸，R2 负责分发；普通构建不扫描／上传原图，避免 CI 依赖素材盘和密钥 |
| 交互与性能 | 搜索和看图器按需加载，正文有无 JS 回退；页面使用原生滚动，星空在遮挡／滚动／减少动态条件下暂停，当前无需增加全局状态框架 |
| 工程验证 | `npm run check` 覆盖类型、单元、内容与构建；前后台浏览器测试已存在，但仍未纳入自动 PR 检查 |

## 后续建议与边界

1. **优先补 PR 检查。** 当前 Pages 工作流只在 main 推送或手动触发时运行 `npm run check`；建议另加 PR 验证，并将公开页面及后台浏览器测试作为独立检查。没有本轮直接改云端流程，避免把尚未跑过的远端环境标成已验证。
2. **逐步集中配置业务约束。** TypeScript 检查与后台字段检查并不覆盖所有手写配置的非空、唯一性、权重等业务条件。后续按实际维护需求补共享校验；本轮已先补真实内容会受影响的系列归属和资源收录引用。
3. **按职责拆分较大文件。** 后台 `scripts/admin/ui/app.js`、内容检查、分类手风琴和星空组件仍较长。下一次修改这些区域时，可以抽出表单状态、请求协调或图形运行时；目前没有证据支持为了缩短文件而重写框架。
4. **保留本地后台定位。** 成组保存有版本预检、历史备份及普通异常处理，但不等于跨文件数据库事务，进程或机器突然中断的恢复仍需要人工核对。若未来改为公网后台，需要单独设计认证、授权和发布流程。
5. **持续维护依赖 override。** 当前 KaTeX override 避免数学插件带回旧版本；上游升级后再评估移除，升级 Astro 时也重新核对 [程序化 preview API](https://docs.astro.build/en/reference/programmatic-reference/)，该接口仍有实验性说明。
