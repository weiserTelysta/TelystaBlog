# 博客图片点击放大

## 问题与计划

博客正文的 Markdown 图片仅渲染为 `<img>`，没有绑定放大交互；资源页已有 PhotoSwipe，但文章未接入。修复不改变文章宽度、图片滤镜、圆角和段落间距。

1. 复用现有 PhotoSwipe 5 依赖，文章侧按需加载单张图片看图器，不改写资源页交互。
2. 普通正文图片增加可聚焦的原生图片链接，支持点击／Enter 打开放大；已有作者链接保持原行为。
3. 以浏览器实际加载的图片及真实尺寸展示，不假定所有 CDN 图片都有清单尺寸。支持缩放、拖动、手机双击／双指手势、关闭按钮和 Esc。
4. 隔离背景滚动，关闭后还原焦点；页面切换清理实例；减少动态效果时禁用过渡。模块加载失败回退图片链接，无 JavaScript 时仍保留正文图片。
5. 验证真实文章桌面／手机布局、键盘、缩放、异常与反复打开关闭，运行类型检查、测试和构建后推送。

参考：[PhotoSwipe 官方选项](https://photoswipe.com/options/)与[实例生命周期](https://photoswipe.com/methods/)。

## 实现与使用

- 正常写 `![说明](图片地址)` 即可。客户端自动增强正文内的 `<img>`／`<picture>`，不需要逐篇改 Markdown。本地图片与 R2／其他 HTTPS 图片使用相同入口。
- 图片增加放大光标和键盘焦点；点击或 Enter 打开单张图片看图器。点击图片、缩放按钮或 Z 切换缩放；滚轮缩放、拖动平移，手机支持双击与双指缩放。Esc、关闭按钮或背景可关闭。
- 加载时使用 `currentSrc` 与浏览器真实尺寸；本轮不额外下载原始 PNG、不提升源图本身的清晰度，也不增加文章内上一张／下一张。已有作者链接不被拦截；特殊图片可在自身或容器加 `data-no-lightbox` 排除。
- PhotoSwipe 核心在第一次点击时按需加载，样式仅由文章页引入。模块失败时跟随原生图片链接；尚未加载或失效的图片直接走原生链接，不打开空弹层。无 JavaScript 时仍显示原始正文图片。
- 看图器内保持源图原色，不沿用正文的压暗滤镜。文章阅读宽度、图片大小、圆角、滤镜和间距保持不变。
- `src/lib/articleImageRuntime.ts` 负责渐进增强、失败回退和页面生命周期；`src/components/article/articleImageViewer.ts` 负责 PhotoSwipe 实例、焦点和滚动恢复；文案统一放在 `src/config/pages/article.ts`，未修改资源看图器。

## 验收

- 修复首轮浏览器测试发现的 Tab 越过最后一个控件、进入浏览器工具栏的问题；增加正向／反向焦点循环。打开动画期间立即点击关闭或按 Esc 会在动画结束后关闭，不残留滚动锁。
- 本地完整 `npm run check` 通过：类型检查零错误／警告、110 项单元测试通过、87 个内容文档零错误／警告、31 个页面构建成功。Windows 类型检查沿用本地官方 WASI 后端，未修改系统策略。
- 全量公开页面浏览器回归 52 项通过，含新增 8 项：390／1440px 真实图片与阅读位置、缩放按钮／Z／滚轮、双指触摸、键盘循环与 reduced motion、反复打开与页面切换、作者链接／picture／坏图、模块失败回退、无 JavaScript，以及动画期间立即关闭。资源页原看图与下载交互回归通过。
- 已查看桌面与手机截图，正文宽度仍分别为 760px／358px；看图器使用独立暗色背景与原色图片。截图、构建日志和浏览器日志位于忽略目录 `.tmp`。
