# 本地后台使用与维护

当前版本：2026-09-15，本地管理界面与新增流程。最新计划、调研与验收见 [UI 与功能补全](admin-ux-plan-2026-09-15.md)，文章表单与预览见 [写作阶段记录](admin-writing-2026-09-15.md)。

## 启动

在仓库根目录运行 `npm run admin`，打开终端显示的 `http://127.0.0.1:4323/`。请使用这个地址，`localhost` 是另一种 Host，会被来源校验拒绝。端口被占用时服务不会抢占；PowerShell 可先设置 `$env:TELYSTA_ADMIN_PORT = '4324'` 再启动。

另开终端运行 `npm run dev`，后台的「打开网站预览」默认指向 `http://127.0.0.1:4321/`。若 Astro 使用其他端口，以其终端输出为准。后台可以单独启动；内容错误导致 Astro 预检失败时，仍可打开文章源码修复。

后台只在电脑上运行，静态构建不包含管理入口或 API。不要将其转发到公网。退出启动终端的服务后即可停止，原来的源码、Git 和维护命令仍可正常使用。

## 保存、预览与检查

1. 选择功能并编辑。问候语和链接支持列表操作；引用中的分类、系列、头像 ID 与派生代码受保护。
2. 「查看保存差异」显示当前文件和拟保存源码；只是校验，不写文件。目前是完整源码对照，尚无行级高亮。
3. 保存后检查网站效果。后台不会自动提交、推送或上传 R2。
4. 在「检查与历史」运行项目检查，或终端执行 `npm run check`。检查运行期间暂停后台保存，但不会锁住 VS Code；检查时也应避免其他编辑。
5. 查看 `git diff`，将相关图片与引用一起提交，再 push；以 Actions 的具体提交部署结果判断是否上线。

保存使用文件 SHA-256 版本。若 VS Code、另一个后台标签页或 OneDrive 改动过文件，保存返回冲突，页面输入保留。先复制自己的输入，再重新读取并人工合并；不能连续点击保存来强制覆盖。切换功能或离开页面时有未保存提示。

旧文件会留副本在被 Git 忽略的 `.tmp/admin-recovery/`：同一 UUID 的 `.bak` 是旧字节，`.json` 记录路径、旧版本和时间。没有自动恢复按钮，这也不是长期备份；需要恢复时先用 Git／编辑器逐文件对照。外部程序未参与事务锁，最后校验与替换之间仍存在很短的竞争窗口，不要同时编辑同一文件。

## 功能边界

| 功能 | 当前使用方式 |
| --- | --- |
| 站点与首页 | 名称、描述、分享图、备案文字、顶部导航、既有首页区块；源码中的派生表达式只读 |
| Hero | 新增／编辑／删除／搜索句子，配置昼夜偏好与权重；用当前未保存表单按指定小时试抽样，复用网站算法 |
| 标签页祝福 | 独立字符串列表，模拟离开与返回的文字；不会改变后台自己的标签页身份 |
| 头像 | 列表选择身份，编辑名字、alt、色调、权重与启用；「新增头像身份」上传并生成 384×384 WebP、32/48px PNG favicon 和配置。已有 ID 与图片引用受保护 |
| 分类与角色 | 「新增分类与角色」同时建立分类、角色图片、英文题签、中文介绍和文章目录；资料与角色页可相互跳转。宽:高 2:5 裁切预览；八种光泽下拉选项与前台共享纹理 |
| 系列 | 「新增系列」选择已存在的分类；已有系列可编辑介绍，新增后立即出现在文章表单中。无公开文章的系列不会进入公开系列索引 |
| 社交与二维码 | 社交链接显示与网站相同的 SVG 图标；二维码支持选择已有图片、上传无损 WebP、填写 R2 图片地址 |
| 文章 | 搜索、新建草稿、元数据表单、原文编辑、草稿正文预览。新文档从日期文件名／分类目录补全；已有路径不能重命名或删除 |
| 素材 | 检索已登记 R2 图片、头像、本地角色图、二维码、favicon、`public/media` 新图；复制 `asset:` 键或图片地址。文章 Markdown 优先用公共显示图 URL，本地文章目录图片使用相对路径 |
| 历史 | 展示工作区文件列表、最近 20 次配置／内容提交和本次检查日志；不提供恢复或远程发布 |

文章信息表单包含标题、双语摘要、日期、分类、系列、序号、草稿、标签和封面。未显式填写的字段展示自动值；先点「应用字段到源码」，再校验或保存。应用只修改内存中的源码，不写文件；选择无系列时同时清空序号。保存会检查分类与系列一致、序号有效和现有文件版本。若先改了源码，请重新读取表单后编辑，避免两套待保存内容相互覆盖。

「校验与预览」展示当前未保存正文、补全元数据以及源码对照。支持常见 Markdown、表格、代码、原生 MathML 公式、R2 图片和允许的本地位图；原始 HTML 显示为代码，链接不跳转，不运行脚本／评论。预览位于无脚本、无同源权限的 sandbox iframe，有独立 CSP。简谱引用、代码高亮、最终字体／间距及完整文章布局仍通过网站构建核对；这不是像素级生产预览。

表单只替换修改字段的 YAML 值范围，保留正文、未知字段、无关注释与原换行。带锚点、自定义标签或复杂列表注释的字段要求回到源码编辑；不会自动丢弃这些信息。完整 Markdown 原文仍可直接编辑，参见 [写作指南](article-authoring.md)。草稿不会进入公开网站，但保存到公开 Git 仓库后不具备保密性。

新增二维码：在「QQ / 微信二维码」选择文件，点「处理并使用二维码」，系统生成无损 WebP 并回填 `/media/qr-<内容哈希>.webp`，再保存配置，最后人工扫码。已有图片使用 `src/assets/contact/qq.png` 这类源码资源地址，构建时映射为实际图片 URL；新图使用 `/media/…` 公共路径，也支持 `https://assets.telysta.com/…`。配置字段统一为 `imageSrc`，不再要求只填文件名。

新增身份／角色接受 PNG、JPEG、WebP，限制 8 MiB、2400 万像素，拒绝动图。头像居中裁切；角色图保持原始比例、最长处理范围 1200×2400，再按卡片参数裁切展示。文件自动命名放入 `public/media/`，不会覆盖旧图，随 Git 部署即可使用。原 R2 头像保留原地址。若需要精细头像裁切，先准备正方形图；已有图片替换与 R2 自动上传尚未开放。

普通文章图片仍可在「素材选择」上传到 `src/content/weiser-posts/` 下已有目录（PNG／JPEG），这条原文件上传路径不自动转图；不要与头像／角色／二维码的处理流程混淆。

上传与修改引用是两步操作。失败会保留旧图；放弃引用编辑可能留下新上传但未引用的图片，提交前检查。R2 图像准备、原图同步、cover 和清单生成继续沿用 [素材维护](cdn-assets.md)，不是再建一份媒体存储。

身份／分类新增属于成组保存：预览只计算文件内容，保存前核对全部配置版本；出现普通写入失败时，只恢复仍属于本次操作的字节。已有表达式、注释保持不变。新分类目录会包含 `.gitkeep`，可以立即创建文章。该机制不是数据库事务，进程被强制终止／断电仍需结合 Git 和恢复副本检查；不自动删除分类、系列或 R2 对象。

## 开发与验证

- `scripts/admin/config.ts`：固定配置声明、AST 字面量读写和业务校验。不执行表单输入，新增支持字段应同时补约束。
- `scripts/admin/catalog.ts`：专门的身份／分类／系列新增模型、图片处理、版本预检和成组写入；不通过放开任意配置对象来实现新增。
- `scripts/admin/store.ts`：真实路径校验、SHA 版本、临时写入和旧字节副本。拒绝目录联接、路径大小写不匹配、越界与 Windows 保留名。
- `scripts/admin/server.ts`：回环 HTTP、请求来源和会话令牌、固定 API、Markdown 校验、素材索引与受限上传。
- `scripts/admin/post-fields.ts`：文章字段白名单、YAML 节点范围修改与往返校验；不重写整个 frontmatter。
- `scripts/admin/post-preview.ts`：独立草稿 Markdown 渲染，HTML 转代码、移除导航、原生公式与隔离预览。
- `scripts/admin/ui/`：独立原生表单界面；编辑文字使用 `textContent`，不将原文插入 HTML。
- 光泽名与 ID 在 `src/config/visuals/foilPresets.ts`，纹理在 `src/styles/category-foil.css`；社交 SVG 在 `src/config/visuals/socialIcons.ts`。前后台共用这些定义。
- `npm run test:admin`：在临时仓库副本运行桌面／手机浏览器流程，不改真实配置。普通 `npm test` 含后台 API 与文件保存测试。

配置现有值可原样往返，改变的字面量才重写；未知代码不作为可编辑值。表单列表至少保留一项，避免清空后丢失字段结构；手动源码中已经为空的列表仅展示。包含作者注释的列表若增删无法保持注释，会拒绝该结构操作，仍允许编辑已有值。语法损坏的 TS 需在编辑器中修复。类型与基础约束通过不等于所有外部链接／图片可用，完整构建和实际预览仍是提交前步骤。
