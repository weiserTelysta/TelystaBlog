# Telysta UI 审查清单

## 修改前

- 确认用户是否明确要求重新设计；没有时按局部修复处理。
- 定位共享 token、排版角色、响应式断点和交互状态来源。
- 检查页面真实 DOM，避免用 CSS 掩盖 Markdown 或语义错误。
- 为受影响页面记录桌面和移动端基线。

## 代表页面

- `/`：首页身份、星空、导航和留白。
- `/blog/`：时间线、栏目入口和内容密度。
- 一篇长文章：标题、正文、代码、公式、目录和系列导航。
- `/resources/`：筛选、瀑布流、详情层、预览和下载。

## 视觉

- 深蓝黑背景、正文、月光蓝和灰粉角色没有漂移。
- 没有新增高饱和大色块、强发光或厚重面板。
- 正文阅读宽度、行高、段落节奏和标题层级稳定。
- 图片没有造成跳动、异常裁切或过大的首屏负担。
- 200% 缩放和移动端没有横向裁切。

## 交互与焦点

- 鼠标、键盘和触摸都能完成主要操作。
- `:focus-visible` 清楚可见，鼠标点击不会留下错误的选中状态。
- 对话框打开后焦点进入当前对话框，Tab 不进入被遮挡层。
- Escape 只关闭最上层交互，关闭后焦点回到触发按钮。
- 本地滚动区域不被全局 Lenis 接管。
- 快速重复打开、关闭或切换最终停在用户请求的状态。

## 动效

- 动效解释状态，不成为独立装饰表演。
- 没有 bounce、elastic、明显大缩放或持续抢眼循环。
- `prefers-reduced-motion: reduce` 下功能保持完整。
- 布局动画和局部 hover 不争夺同一个 transform。
- 初始、中间、结束和中断状态都没有闪烁或布局跳变。

## 可访问性

- 正文和重要元信息满足目标对比度。
- 标题层级和列表语义正确。
- 按钮、链接和对话框有可理解名称。
- 状态不只依赖颜色或动画。
- 页面在 JavaScript 局部失败时仍保留基本导航和内容。

## 验收

- 自动检查和构建通过。
- 浏览器控制台没有新增错误。
- 所有视觉差异都可以由用户请求或可访问性缺陷解释。
- 未触及页面在抽查中没有布局、配色或交互变化。
