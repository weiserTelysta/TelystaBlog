# Telysta 书室入库

保持原文件可找回，固定书籍身份，分别处理本地资料、R2 对象和 Git 网站元数据。先读取仓库当前实现，不把既有盘点数量当作新批次的目标数量。

## 先确认任务范围

- 从会话确认本次指定哪些书，以及是否授权上传 R2、提交 Git、推送部署。已有授权继续有效；“只写 Skill／先整理／暂不提交这些书”不授权上传或发布新书。
- 不扫描后把整个 Books 目录自动上传。新书可能暂存在根目录、未收进旧 CSV；原有清单不是新书齐全与否的唯一依据。
- 不移动、删除或改名本地原书。要分类整理，优先在临时入库批次中保留分类路径；修改原目录须有相应任务授权。
- 用户明确要求去重时，只移除完整 SHA-256 和字节数均相同的副本，操作前重验所有保留件与副本。优先保留已分类目录的一份；副本先移至 Books 之外的私人隔离目录，记录原路径、保留路径、哈希和恢复清单。不同格式、版次、译本、卷次或仅书名相同的不视为绝对重复，不据此删远端对象。
- 不因待核对或不在首页展示而删除本地书籍或已有 R2 对象。分类／首页可见性属于元数据操作；远端删除是另一项操作，需单独授权。

## 入库需要的信息

每个文件记录：本地准确路径、格式、字节数、完整 SHA-256、对应中图类号及类名、标题、作者／编者、证据来源，以及获准公开的范围。译者、出版社、出版年、语言在有依据时补充。封面从文件内提取；缺失时用文字占位，不编造封面。

作者以题名／版权页、出版社或图书馆书目核对。EPUB OPF 可以辅助，不能把版次、ISBN、扫描工具、出版社或译者误当作者。多人合集注明署名完整程度；无法确认时保留可见的待核对状态，不猜填。需要网页核对时记录具体来源 URL。

固定 ID 约定为 `WEISER` 加文件 SHA-256 前12位，首次写入后保留；文件名、标题或目录变动不重建 ID。全 SHA-256用于校验与短编号冲突检查。替换不同版本或合并格式时先判断作品／版本关系，不因同名覆盖原文件或另书的对象。

## 实现入口

普通编辑只修改对应大类JSON，不再逐书创建Markdown。每个文件使用 `{ "category": "K", "booklists": [{ "clcCode": "K27", "clcName": "中华人民共和国史", "books": [...] }] }`，书目顺序不影响固定ID。分组使用实际核实的最细类号，层级深度可以不同；“二级Booklist”是网站导航层级，不表示所有书都要退回相同两位类号。字段及完整例子见 [references/catalog-json.md](references/catalog-json.md)。`imported/` 已清空迁移，后续直接维护JSON；暂不发布的新书保留草稿，不顺带上传或部署。

`access` 为 `public` 或 `protected`，与 `draft` 分开。改变访问状态使用 `npm run library:access -- --id WEISER... --access protected`（或 `public`），工具保留完整元信息并生成／撤销公开占位；不能只藏卡片。邮箱Secret、会话令牌和完整受保护书目不提交公开Git。

- schema 与下载域约束：`src/lib/ebooks/ebookSchema.ts`。
- R2 公开域、页大小与分类：`src/config/library.ts`。
- 书架与详情：`src/components/ebooks/`、`src/pages/ebooks/`；常规加书修改数据，不逐书修改组件或路由。
- 增量盘点与完整性：`scripts/library_delta.py` 读取 Windows 原生盘点及完整 SHA-256，只生成私人差异报告；旧严格 CSV 流程保留于 `scripts/library-catalog.py`。
- 类号、显示名及来源登记：`data/library/clc-mappings.json`；内容构建检查类号与名称，新增或修订分类时同时维护登记表和分类 JSON。
- 封面与初始网页记录：`scripts/prepare-library-books.py`；生成到 `.tmp/` 后审查，再加入正式书目。
- 访问控制与阅览：`workers/library-gateway/`、`src/lib/ebooks/libraryAccess.ts`、`src/pages/ebooks/read.astro`；PDF新标签页交给浏览器阅览并保留鉴权与Range；EPUB／MOBI／AZW3按需加载并禁用书内脚本，保留原文件。
- Worker书目准备：`npm run library:gateway:prepare -- --scope <已核验全量ID数组JSON>`，读取公开JSON和本地私有JSON，生成忽略于Git的服务端catalog；名单包含继续服务的旧书与获准新增书，部署前必须运行，缺少名单或完整私有书目时停止部署。
- `categoryOnly` 仅为发现方式，不是访问锁；解锁后的受保护条目可进入全部藏书、分类及搜索。原有 `data/library/presentation-overrides.json` 只用于离线准备旧书目，日常以分类JSON为准。

书室UI沿用根目录 `DESIGN.md`：上一页、页码、下一页紧邻居中，保留可直接点击的原生链接与焦点；不能分散至两侧或仅以输入框替代。阅读器占满视口，保留紧凑工具栏和脚本隔离，不将书籍正文预加载进书架。
- Windows EPUB 元数据：`scripts/inspect-library-epub.ps1`。
- 明确名单复制：`scripts/sync-r2-library.ps1`，默认 dry-run；`-Apply` 才上传。
- 正式发布范围以分类JSON的 `draft`、`access` 和Worker书目为准，不能把旧盘点脚本的全库输出当成自动发布授权。

新增批次、R2 验证与提交细节见 [references/workflow.md](references/workflow.md)。账户权限、服务端部署和受保护元信息维护见 [references/access-control.md](references/access-control.md)。

中图法的大类与当前细分类映射见 [references/clc.md](references/clc.md)，新增书籍归类与 Booklist 建立时读取。现行结构、字段样例及历史盘点见仓库 [docs/ebooks.md](../../../docs/ebooks.md) 与 [docs/library.md](../../../docs/library.md)。

匿名下载每日10个不同文件、续传去重及Secret/DO部署规则见 [访问控制](references/access-control.md#匿名下载每日额度2026-11-22)。常规入库不得重置配额或绕过网关。

## 完成标准

对账本批次指定文件与实际上传对象，确认文件大小、可用哈希、封面和匿名公开链接；执行适用的内容校验、类型／单元检查和生产构建。报告实际入库／上传数量、保留的未核验项、验证方式、Git 提交和部署状态。没有测试的部分不宣称通过。

当前已知约束：WSL 枚举曾静默漏掉目录；Windows 原生枚举是原库盘点依据。rclone 对全角标点的虚拟路径可能与 Windows 文件名不同，公开 URL 必须来自实际对象 key。不要打印或提交密钥、rclone 配置、原始私人 `_manifest.csv`；认证只在本地工具中使用。

## 中图法分类与书目编目规则

以《中国图书馆分类法》第五版（CLC）为分类依据，优先使用本仓库已经核实的分类映射。新增类号时必须核对权威分类表或可信图书馆编目记录，不得凭模型记忆虚构细分类号。

### 分类原则

**以作品内容为依据。** 优先考察题名页、版权页、内容简介、目录、前言及正文。文件名、原始文件夹和 EPUB OPF 只能作为辅助证据，不得直接决定分类。

**采用主要分类与辅助主题分离的原则。** 每条书目确定一个主要中图分类号；跨学科内容用主题标签或辅助分类字段表示，不因涉及多个领域而自动生成多份书目或复制多个 R2 对象。

**优先选择准确且经过核实的最具体类目。** 不要求所有图书具有相同的分类层级。不能证明细分类号有效时，退回已核实的上级类目，并将细分类保留为待核对状态。

**不得混淆作品体裁与研究对象。** 历史小说、历史研究、宗教经典、宗教史研究、漫画作品与漫画理论研究应按具体文献的主要内容和分类规则分别判断。

**支持分类复核与修订。** 对主题复杂、资料不足、版本不明或存在多个合理类号的书籍，记录备选分类及依据，并标记人工复核。不得为了完成批次而强制确定一个未经核实的细分类号。

### 分类证据

每次新增或修改分类，应记录分类依据、参考来源 URL（如有）、分类法版本、核对状态与核对日期。已有同书同版本的可信图书馆记录应优先用于比对，但仍需判断其适用性。

CIP与初步主题分类不一致时，单列冲突逐项复核，不能只采纳相同前缀的类号而静默忽略其他CIP。旧版类号、复分类号和一书多类号须保留原始记载；采用现行馆藏或内容归类时，记录原CIP、采用理由和依据。例如旧游戏设计书的TP311.5可依据现行编目归TP317.6，不能把旧类号机械套回，也不能不作说明就略过差异。

### 分类与存储解耦

分类号是可修订的书目元数据，不是永久书籍身份。

分类修订不改变固定书籍 ID，不自动移动本地原书，不自动删除或重传已有 R2 对象。如果网站展示分类与对象存储路径不同，以经校验的实际对象 Key 生成下载链接。

已上传文件的 R2 对象 Key 应作为独立、持久的存储字段记录。分类修订默认只更新书目元数据，不重新生成对象 Key，不移动或复制已上传对象。只有在明确授权存储迁移时，才执行迁移，并在验证新对象及引用关系后另行处理旧对象。

### 分类验证

入库前验证分类号与类名一致、分类号存在于已核实映射、上下级关系合理、来源信息可追溯。

无法核实的分类不得标记为已确认。仅改变分类元数据时，不执行文件上传或远端对象删除。

## 线上提交资源

正式用户的上传先进入R2私人 `incoming/<用户ID>/<上传ID>.<格式>`，D1保存所有者、资料及审核状态。审核通过不自动发布。入库Agent仍需按本Skill核对标题、作者、文件哈希、中图分类和访问范围，再更新正式书目、网关与网站。不要把incoming对象自动透传为公开下载，也不要改动他人的上传资料。Console中的文章／配置编辑属于云端草稿，当前网站发布源仍是Git，保存数据库不等于已部署。
